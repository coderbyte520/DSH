# Agent Note: 对 shell 结果的机械 verifiable-reward 打分

Status: implemented

[English](2026-10-12-verifiable-reward-scoring.md) | 中文

## Problem

harness 的终止权都是模型判断。[evaluated Ralph 工具](../../../../packages/workflow/tool-ralph-evaluated/README.zh.md)与[目标回合认证器](../../../../packages/goal/goal-evaluator/README.zh.md)读取工作区并返回 verdict，而这个 verdict 的可信度只等于产出它的评估器。没有任何东西把一次运行的可观察事实——执行的命令、退出码、通过或失败的测试——变成可供数据集构建方筛选、跨 rollout 比较或回放的持久分数。工具结果携带这些事实，但只是作为单次调用的模型可见记录。

## Decision

交付 [`@vreal/dsh-verifiable-reward`](../../../../packages/reward/verifiable-reward/README.zh.md)：一个只观察的消费方，对 shell 结果做机械打分，并为每次匹配到的调用追加一个可忽略的 `reward/check` 会话事件。分数是命令字符串与规范工具结果的纯函数——有序的首次匹配即生效的命令检查、退出码、沙箱拒绝、测试计数提取、罚分模式，结果夹到 `[0, 1]`。没有模型参与，因此同一份日志总是得到同一分数。

### 工具流水线中的只观察阶段

观察者挂到 `tools/result`：该阶段在结果定型之后运行，并把抛错的监听者隔离为一条警告。`tools/post-execute` 可以替换或阻断结果，且在那里抛错会变成 `isError` 结果，因此一个只做审计的打分器若挂在那里，就获得了让它本该描述的那次调用失败的能力。两个阶段都按 `exec.agent` 做作用域过滤，也都能收到 Code Mode 的子派发，这正是 rollout 需要的：被打分的调用是携带真实命令的内层 shell 调用。

打分从不改变结果，因此挂载该插件既不能改变模型看到的内容，也不能改变持久化工具日志，或一次调用是否报告成功。

### 配置属于 schema，编译属于编译器

`Config` schema 在加载时校验类型、种类与取值范围，因此空的工具名、未知的检查种类、负权重或未知作用域，会在与其他插件配置错误相同的位置失败。打分编译器只补充 schema 无法表达的部分——模式源为空或无法编译——并在失败中指明出错的检查或罚分模式。

计数提取的覆盖模式以 `g` 标志编译，因为 `matchAll()` 需要它；命令模式保持非全局，因为 `test()` 在全局模式上会推进 `lastIndex`，进而跳过匹配。没有捕获组的模式把每次匹配记为零，而不是在观察者内部抛错。

### 专用可忽略事件

该记录是独立的 `SessionEventMap` 成员，以 `ignorable: true` 追加。会话事件按成员类型化并各自版本化，因此把奖励字段加进已有的工具事件会迫使每个读取方都认识这个新字段；一个可被读取方跳过的独立成员既让未知读取方继续工作，也保证丢失该记录不会改变会话重建——因为没有 fold 消费它。事件只携带结构化事实——调用标识、工具、命令、匹配到的检查、退出码、解析出的计数、罚分命中、得分与流可用性标记——绝不携带捕获的输出文本。

### 一次调用如何打分

一次被打分调用在前台进程以 0 退出且未被沙箱拒绝时从 `1` 起步，否则从 `0` 起步。`test` 检查在 stdout 既未截断也未落盘时用 `passed / (passed + failed)` 替换该基线，数据来源是默认的 `N passed` / `N failed` 摘要、已配置的覆盖模式，或在未配置覆盖时的 Go `ok`/`FAIL` 包标记；其他种类一律跳过解析。每个命中的罚分模式在夹取之前扣减其罚分。错误结果因为没有输出可读，得分为 `0` 且无计数：此时只有命令作用域的罚分模式可能命中。

## Testing

包测试在脚本化的 shell 实现之上驱动真实的 `dsh-tools` 注册表，因此观察者看到的与生产完全一致：匹配到的调用记录一个事件且工具结果逐字节不变；禁用插件、未被观察的工具名、未匹配的命令、缺少命令参数、非前台规范值，以及没有归属 agent 的调用都不记录任何内容；错误结果仍会记录它能扫描到的命令作用域罚分命中。一个用例直接调用 `apply`，证明内置默认值无需 Loader 归一化即可解析；一个用例覆盖部署自己的检查、权重、作用域与罚分；还有一个用例卸载插件，表明观察者是 effect。

打分核心按纯函数覆盖：默认提取与覆盖模式的每个分支、Go 标记、截断、落盘、被拒绝与被信号杀死的各种结果、罚分夹取、加权轮次聚合，以及可验证侧与模型侧的全部组合。覆盖率为仓库门禁要求的每文件 100%。

## Alternatives considered

- **在 `tool-bash` 与 `tool-pwsh` 内打分** —— 否决：同一套打分策略会有两个归属方，并在 POSIX 与 Windows 工具之间漂移；每个挂载 shell 工具的部署都会背上它未必想要的打分。
- **在 `tools/post-execute` 打分** —— 否决：该处的监听者失败会变成调用失败，使一个纯信息性的打分器获得它不该拥有的错误通道。
- **在 goal 评估器内推导分数** —— 否决：那个消费方用模型判断认证单个终结声明，而奖励记录的主体、节奏与生命周期都不同。
- **在 `tool/result` 上加奖励字段** —— 否决：会话事件表按成员类型化，新字段会让该记录成为每个读取方的必修知识。
- **把分数折叠进会话投影** —— 否决：一个影响重建的派生分数会让丢失记录变成正确性问题；`ignorable: true` 恰恰声明了相反的事实。
- **让模型贡献基础分** —— 推迟而非否决：`combineScores` 已实现 `alpha * verifiable + (1 - alpha) * model`，目前没有任何东西产出模型侧分数。

## Consequences

- 每个挂载 base bundle 的组合现在都会为匹配到的 shell 调用追加一个可忽略事件，因此会话日志随测试与构建活动增长；不认识该事件类型的读取方会跳过它。
- 投影、请求推导与模型都不受影响，因此移除该行的部署会精确恢复此前的日志。
- 训练奖励的可验证一侧现在已在日志中；采样、过滤与数据集导出一侧尚不存在，聚合辅助函数已为其导出。

## Known limitations and deferred work

- **只用 RegExp 匹配** —— 检查把命令字符串当文本测试，因此通过脚本、别名或门禁包装器运行测试而不匹配任何已配置模式的调用不会被打分。
- **计数来自打印的摘要** —— stdout 被截断或落盘时跳过测试解析，摘要格式不同的运行器需要配置计数模式。
- **尚无消费方** —— 目前没有任何东西把这些记录折叠进数据集或训练奖励；聚合辅助函数还没有调用者。
